## 2. Логика текущей структуры

Структура следует **двухуровневой логике**:

```
AI-Cinema/
├── Глобальный уровень (переиспользуется во всех фильмах)
│   ├── _knowledge_base/   — теория и гайды
│   ├── _characters/       — библиотека персонажей
│   └── _prompts_library/  — шаблоны промптов
│
└── Уровень фильма (конкретное производство)
    └── films/film_XX/
        ├── characters/    — кто: профили и датасеты
        ├── script/        — история: синопсис, сценарий, источник
        ├── production/    — исполнение: промпты изображений, видео, музыки
        ├── storyboard/    — визуальный план (пустой)
        └── assets/        — сгенерированный контент (пустой)
```

Внутри фильма разделение по ролям правильное. Проблема в том, что **заполнены только слои "кто" и "история"**, а слои "визуальный план" и "контент" — пустые.

Obsidian задуман как навигационный слой поверх репозитория, но остался незаполненным скелетом: `Films/` и `Knowledge/` — пустые папки, Dashboard ссылается на несуществующие файлы.

## 4. Чего не хватает для многоагентной системы

Сейчас проект написан для **одного агента с контекстом в голове**. Для мульти-агентной системы нужно семь вещей:

---

### А. Файл состояния (State) — не существует нигде

Агент должен знать **текущий статус каждого кадра**: в очереди / генерируется / одобрен / отклонён / используется как референс.

Сейчас статус — только в голове пользователя или в общем чеклисте `CLAUDE.md`.

**Нужно:** `production/status.md` или `status.json` с построчным состоянием каждого из 35 + 23 = 58 кадров датасета и 8 сцен фильма.

---

### Б. Раскадровка по сценам — папка пустая

`storyboard/scenes/` — полностью пустая. Это **центральный артефакт** между сценарием и видеопромптами.

Агент-раскадровщик не может начать работу, агент-генератор не знает, что снимать.

**Нужно:** файлы `scene_01.md` … `scene_08.md`, каждый с трёхслойной структурой:
- Литературный слой (кто / что / зачем / эмоция)
- Режиссёрский слой (тип плана / ракурс / движение камеры / свет)
- Технический слой (промпт + референсы + инструмент)

---

### В. Реестр ресурсов — не существует

Когда изображение сгенерировано — его URL и статус некуда записать. Следующий агент не знает, что M1 (портрет Человека) уже готов и где лежит.

**Нужно:** `assets/registry.md` — реестр всех сгенерированных ресурсов:
```
| ID  | Тип    | Описание          | Путь / URL | Статус   | Используется в |
|-----|--------|-------------------|------------|----------|----------------|
| M1  | image  | Человек портрет   | ...        | approved | сцены 1,3,5    |
| M2  | image  | Человек полный рост| ...       | approved | сцены 2,4      |
```

---

### Г. LoRA — упомянута, но не оформлена

В промптах упоминаются LoRA `bonfire_man` и `taiga_dog`, но нет файла с параметрами обучения, статусом (обучена / нет), URL модели, силой применения (1.0–1.2).

Агент-генератор не знает, нужно ли обучать LoRA или она уже готова.

**Нужно:** `production/lora.md` — параметры и статус обеих LoRA.

---

### Д. Агентные инструкции — не существуют

Нет папки `agents/` с описаниями ролей. Каждый агент должен знать: что читает на входе, что пишет на выходе, какие файлы трогает.

**Нужно:** определения агентов, минимум четыре:

| Агент | Вход | Выход | Трогает |
|---|---|---|---|
| Раскадровщик | `script/` → | `storyboard/scenes/scene_NN.md` | storyboard/ |
| Генератор кадров | `storyboard/` + `characters/` → | обновляет `assets/registry.md` | assets/, production/status.md |
| Видеограф | `registry.md` (одобренные кадры) → | видеопромпты + записи в registry | production/, assets/videos/ |
| Монтажёр | `assets/videos/` → | описание склейки + финальный чеклист | production/ |

---

### Е. Протокол передачи кадров — не описан

Правило «последний кадр клипа N = первый кадр клипа N+1» существует в теории (в production_workflow.html), но нет структуры, где записывается:

> «Финальный кадр сцены 3 — файл `assets/images/scene_03_last_frame.jpeg`, использовать как start image для сцены 4»

**Нужно:** колонка `last_frame` и `start_image` в реестре ресурсов, или отдельный файл `production/transitions.md`.

---

### Ж. Higgsfield MCP — режим B не имеет конфигурации

Режим B (Higgsfield) описан в `production_workflow.html`, но в репозитории нет:
- конфига MCP (`.mcp.json` или аналог)
- скриптов автоматической генерации
- описания переменных окружения (API-ключи, параметры)

Агент не может запустить режим B, не зная, как подключиться к Higgsfield.
